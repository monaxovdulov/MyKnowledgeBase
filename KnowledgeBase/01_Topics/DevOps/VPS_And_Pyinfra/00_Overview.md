# VPS с нуля через pyinfra — обзор трека

> Карта трека: [[VPS_And_Pyinfra_MOC]]

Учебный трек: учимся администрировать свой VPS на Debian через [pyinfra](https://github.com/pyinfra-dev/pyinfra) с Windows-машины.

## Исходные данные

- Голый сервер у провайдера aeza: Debian, есть только **IP-адрес, root и пароль** (приходят в панели/на почту).
- Рабочая машина: **Windows** с PowerShell.
- В панели aeza есть веб-консоль (VNC) — это аварийный вход, если потеряем SSH.

## Цель трека

В конце сервер настраивается не руками, а одним Python-деплоем:

```powershell
pyinfra inventory.py deploy.py
```

— и этот код лежит в git, повторяем на любом новом сервере.

## Логика порядка шагов

1. [[01_First_SSH_Connection]] — заходим по SSH, создаём своего пользователя с sudo.
2. [[02_SSH_Keys]] — переходим с пароля на SSH-ключи.
3. [[03_Basic_Server_Hardening]] — **руками** делаем минимальную защиту (потом напишем её кодом — так видно, что именно автоматизируем).
4. [[04_Install_Pyinfra_On_Windows]] — ставим pyinfra и делаем первый ad-hoc запуск.
5. [[05_First_Inventory_And_Deploy]] — первые `inventory.py` + `deploy.py`, понятие идемпотентности.
6. [[06_Hardening_As_Code]] — переписываем шаги 1–3 кодом.
7. [[07_Next_Steps]] — факты, тестирование в Docker, несколько серверов.

## Правила безопасности на весь трек

- Перед изменениями SSH-конфига держим **открытую сессию** и веб-консоль aeza под рукой — тестируем вход в новом окне, старое не закрываем.
- Пароли и ключи не коммитим в репозиторий. В git только конфиги и код.
- Сначала руками → понять → потом кодом. Не копировать деплой вслепую.
- Если сервер **не голый** — на нём уже живут сайты и боты — перед `ufw enable` обязательно разрешить их порты (см. [[03_Basic_Server_Hardening]]), а правки sshd делать особенно аккуратно.
