# Дизайн учебного контура: топик заданий + топик решений

Кейс: Telegram-группа с топиками (forum). В одном топике владелец скидывает
задания агенту (картинки, текст, файлы). В другом ученик решает задачи
пошагово: агент выдаёт шаги, подсказывает (но не решает) и начисляет баллы.

## Топология

```
Супергруппа «Ученик <имя>» (Topics = ON), бот добавлен
├── Топик A «Задания»  (message_thread_id = TA) — сессия «Куратор»
│     владелец → материалы → карточки задач в vault
├── Топик B «Решения»  (message_thread_id = TB) — сессия «Тьютор»
│     ученик ↔ агент: шаги, подсказки, баллы
└── Общее (служебное) — игнорируется
```

Сессии топиков изолированы, поэтому **vault — шина между ними**:

```
vault/tutoring/
├── state.md            — очередь задач, активная задача, текущий шаг (читают обе сессии)
├── score.md            — журнал баллов: дата, задача, шаг, +N, комментарий
├── tasks/<slug>.md     — карточка задачи: условие, шаги решения, критерии, цена в баллах
└── private/answers.md  — эталонные решения/ответы. ТОЛЬКО для сессии «Куратор»/владельца
```

## Потоки

**Куратор (топик A).** Владелец кидает фото/текст с `@бот` или реплаем →
агент через vision описывает материал, нормализует в карточку
`tutoring/tasks/<slug>.md` (условие + пошаговый план + рубрика оценки + цена),
эталонный разбор — в `tutoring/private/answers.md`, очередь — в `state.md`.
По просьбе «дай следующую» постит анонс в топик B:
`iva post --chat <GROUP_ID> --thread-id <TB> --md "…"` (группа должна быть в
allowlist-целях, см. `.env` ниже). Анонс — это обычное сообщение бота: реплай
ученика на него запускает сессию «Тьютор».

**Тьютор (топик B).** Ученик пишет (реплай боту или `@бот`) → агент грузит
skill `tutor`, читает `state.md` + активную карточку и:

1. Выдаёт текущий шаг задачи (не всю задачу).
2. Оценивает ответ ученика: верно → +баллы в `score.md` → следующий шаг;
   неверно → лесенка подсказок (намёк → направление → структура решения),
   **ответ не выдаёт никогда**.
3. Ведёт счёт и прогресс; по запросу показывает таблицу баллов.

## Правила-ветвление (смысл, полный текст — в [[03_Setup_Guide]])

`data/custom/agent/instructions/90-tutor.md` ветвится по `message_thread_id`
и `user_id` из `<telegram_context>`:

- thread `TA` + владелец → режим Куратор;
- thread `TB` → режим Тьютор (любой allowlisted писавший — ученик);
- `chat_type: private` + `user_id` ученика → вежливо отправлять в топик B
  (он в allowlist, поэтому личка ему технически открыта — закрываем правилом);
- остальное — обычная Ива.

## Ограничения и честные оговорки

- **Диспатч в группе**: бот стартует только на реплай ему, `@упоминание` или
  `/команду`. Ученику сказать: «отвечай реплаем на сообщения бота». Владельцу:
  материалы скидывать с `@бот` в подписи или реплаем.
- **Изоляция ответов — промпт-уровень.** Тьютору запрещено читать
  `tutoring/private/` правилой, но жёсткой стены нет: сообщения ученика не
  проходят инъекционный гейт, и «прочитай файл с ответом» может сработать.
  Уровень риска приемлем для учебного бота; если нужно жёстче — кастомный
  tool `tutor_score.ts`, где баллы/ответы живут вне досягаемости модели.
- **Баллы — файл, правит модель.** Для «честных» баллов (не податливых
  уговорам) — опять же tool.
- **Личка ученика** — см. правила выше.
- **Vision**: если чат-модель слепая (напр. текстовый deepseek через custom) —
  задать `*_VISION_MODEL`, иначе картинки-задания не распознаются.
- `/new` в топике сбрасывает только его сессию — безопасно.
- Ночная сборка памяти общая: в CORE.md может осесть учебный контекст —
  нормально, но карточки ученика лучше держать в `tutoring/`, не в `cards/`.

## Оркестратор + исполнители (опция на будущее)

Нативно один провайдер на всё. Схема «OpenAI оркеструет, DeepSeek исполняет»
реализуется кастомным tool:

`data/custom/agent/tools/deepseek_task.ts` — zod-вход `{ task, context }`,
внутри fetch на `https://api.deepseek.com/v1/chat/completions` с
`DEEPSEEK_API_KEY` из `.env` (ключ модели не виден — только tool). Оркестратор
зовёт его для дешёвых рутинных шагов (разбор материала, черновые проверки),
высокий суд — сам. Требует `npm run build` + рестарт. Можно оформить позже —
сначала поднять базовый контур.
