# Iva — устройство изнутри

Выжимка из кода `smixs/iva-agent` (v0.5.5). То, что важно для понимания и
настройки; не пересказ всей репы.

## Процессы и поток сообщения

```
Telegram → iva-telegram-poll (long-poll, очередь, durable inbox)
        → acceptance-route → eve-сессия (iva.service)
        → inbound-пайплайн → цикл модели → Outbox → sendMessage
```

- **Мост** (`scripts/poller/`): опрашивает `getUpdates`, складывает апдейты в
  durable FIFO-очередь, батчит по чату, доставляет в eve. Команды `/help`,
  `/new`, `/restart`, `/stop` обрабатывает сам, мимо модели.
- **Inbound-пайплайн** (`agent/lib/telegram-inbound.ts`) — единственный вход:
  allowlist → решение о диспатче → запись в daily-лог vault → медиа (vision /
  Deepgram) → security-гейт на инъекции → контекст хода.
- **Outbox** (`agent/lib/outbox.ts`) — единственный выход: вычистка секретов,
  rich-рендер (Bot API 10.1: таблицы, сворачиваемые блоки, формулы) с
  HTML-фолбэком, нарезка на чанки. «Наивная» отправка мимо Outbox считается
  багом — так гейт нельзя обойти.

## Сессии и топики

**Сессия eve = `(chat_id, message_thread_id)`.** Каждый топик форума — отдельная
сессия со своей историей и своей свёрткой (компакшн между ходами). Сессии друг
друга не видят; общее состояние — только через файлы vault.

На каждый ход модель получает блок `<telegram_context>`:

```
chat_id, chat_type, chat_title, message_id,
message_thread_id, user_id, username, bot_username
```

Это фундамент для развешивания ролей/режимов на конкретные топики и людей
(правила могут ветвиться по `message_thread_id` и `user_id`).

## Кто может писать и когда бот отвечает

- **Allowlist**: `TELEGRAM_ALLOWED_USER_IDS` — список **user_id** через запятую.
  Проверяется `from.id`. Пусто = не отвечает никому (fail-closed). Тот же список
  (плюс `TELEGRAM_DIGEST_CHAT_ID`) — allowlist получателей для `iva post`.
- **Диспатч** (когда вообще стартует ход модели):
  - личка — любое сообщение;
  - группа — только: реплай на сообщение бота, `@упоминание` бота, или команда
    `/cmd`. Остальное игнорируется (и медиа тоже — чужой голос в группе не
    улетит в Deepgram).
- Бот с privacy mode (дефолт BotFather) в группе видит ровно то же —
  команды/упоминания/реплаи. Дизайн кейса под это и рассчитан.

## Точки расширения (`data/custom/agent/`)

| Слой | Куда | Нужна сборка? |
|---|---|---|
| Правила поведения | `instructions/*.md` (общий потолок 4000 симв., грузятся каждый ход) | нет |
| Скиллы | `skills/<name>.md` или `skills/<name>/SKILL.md` (модель грузит по описанию-триггеру) | нет |
| Tools | `tools/<name>.ts` (zod-схемы, компилируются в бандл) | да (`npm run build` / `iva update`) |
| MCP | `connections/<name>.ts` | да |
| Subagents | `subagents/<name>/` | да |
| Плагины | `iva plugin` (папка скиллов+кода+MCP) | да |

Штатное дерево `agent/` перезатирается релизами — своё кладём только в
`data/custom/agent/` и `vault/`. Скиллы и markdown-правила читаются с диска
каждый ход: правку подхватывает следующее сообщение, без рестарта.

В чате фраза «запомни правило: …» → Ива сама дописывает `rules.md` после
твоего «да».

## Память (vault/)

- `daily/YYYY-MM-DD.md` — дословный двусторонний транскрипт (пишется хуком,
  руками не трогать).
- `summaries/daily|weekly|monthly|yearly/` — ночная сборка в 04:00 сворачивает
  вверх, карточки `cards/` (контакты, проекты, решения, идеи).
- `CORE.md` (≤1200 симв.) — в каждом промпте.
- Поиск: `memory_search` (BM25 + граф ссылок), опционально векторный гибрид.
- **Vault один на все чаты** — и личка, и все топики делят его. Это и способ
  связи между сессиями, и поверхность утечки (см. дизайн).
- Vault — приватный git-репозиторий, Ива его сама коммитит.

## Провайдеры модели — важные нюансы

- `MODEL_PROVIDER`: `ollama` | `opencode` | `openrouter` | `codex` | `claude` |
  `custom`. Отдельного «openai api key» нет.
- **OpenAI API-ключ** → `custom`: `CUSTOM_BASE_URL=https://api.openai.com/v1`
  (суффикс `/v1` обязателен), `CUSTOM_API_KEY`, `CUSTOM_MODEL`,
  `CUSTOM_CONTEXT_WINDOW`. `THINKING_EFFORT` на custom не уходит — если
  эндпоинт понимает `reasoning_effort`, включить `CUSTOM_REASONING=1`.
- **Подписка ChatGPT** → `codex`: OAuth (`iva login`), без API-ключа; модели
  по списку подписки.
- **Vision**: на первой картинке Ива спрашивает чат-модель «видишь ли ты
  картинки»; видит — получает пиксели напрямую, `*_VISION_MODEL` не зовётся.
  Не видит — фолбэк на vision-модель (для custom — `CUSTOM_VISION_MODEL` +
  `CUSTOM_API_KEY`, иначе картинка останется без описания).
- **Одна модель на всё**: главный агент, субагенты, helpers, vision, ночная
  сборка. Пер-нодовых провайдеров нет (осознанное решение: «one selection,
  one identity, one usage line»). Учёт токенов — `/usage`.
- Helpers — фоновые задачи до 80 шагов/45 мин, те же tools и модель; только
  из лички владельца (в группе `helper` не доступен — auth это проверяет).

## Безопасность

- Inbound-гейт: веб-страницы, результаты поиска, транскрипты, подписи медиа,
  описание картинки от vision — через санитайзер инъекций; пересланный текст
  помечается предупреждением. **Свой набранный текст не гейтится** — для
  ученика это значит: его сообщения доходят до модели как есть.
- Outbound-гейт: вычистка секретов на каждом выходе.
- Дайджест/отчёты идут в `TELEGRAM_DIGEST_CHAT_ID` (пусть остаётся личка
  владельца — не группа).

## Обновления и эксплуатация

- `iva update` (релизы) / `iva beta` / `iva rollback`; в Telegram — кнопкой в
  `/menu`. `iva doctor` — диагностика, `iva config` — мастер `.env`.
- `.env` читается на старте: правка → `iva restart` (кроме языка — он живой).
- Кастомные слои переживают обновления (live-checkout остаётся чистым);
  при конфликте — `data/update-conflicts/` + skill `update-recovery`.
