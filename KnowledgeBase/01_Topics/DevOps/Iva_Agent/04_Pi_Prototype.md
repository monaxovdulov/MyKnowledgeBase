# Pi-прототип Telegram-тьютора

Решили проверить облегчённую основу на Pi Agent Core вместо полной установки IVA. Telegram-обвязку делаем отдельно на Bot API через `fetch`; от IVA переносим только нужную механику long polling, отправки сообщений и адресации топиков.

## Где лежит код

Исходный код хранится в `vps-config/iva-pi-tutor/` в репозитории. Удобный путь на сервере `/home/devuser/iva-pi-tutor/` — символическая ссылка на этот каталог.

- `src/main.mjs` — long polling, allowlist, маршрутизация по двум топикам, работа с Pi и хранение учебного состояния.
- `systemd/iva-pi-tutor.service` — заготовка user-unit, ещё не установлен и не запущен.
- `.env.example` — имена настроек, секретов в репозитории нет.
- Node.js 24 установлен через nvm в пользовательский каталог.
- Pi-пакеты `@earendil-works/pi-agent-core` и `@earendil-works/pi-ai` версии 1.4.0 установлены.

## Граница приватных ответов

Карточка задачи хранит условие, шаги и критерии в `data/state.json`. Эталонный ответ записывается отдельно в `data/private/answer.txt`. В запрос тьютора попадают только условие, активный шаг и критерии; поле эталонного ответа туда не передаётся. Каталог `data/` исключён из Git, права каталогов — `0700`, файлов — `0600`.

Это защищает от прямого чтения файла кодом тьютора. Текстовая генерация и оценка всё ещё основаны на промпте модели, поэтому перед занятием нужен ручной прогон попыток выманить ответ и проверка реальных заданий.

## Проверка и состояние

Конфигурационный запуск `node --env-file=/tmp/iva-pi-check.env src/main.mjs --check` прошёл без сетевых запросов; Node.js v24.22.1, выбранная для проверки модель `gpt-4.1-mini`, RSS процесса — около 76 МиБ. Это базовое измерение до polling, обработки картинок и диалоговой нагрузки, не замер полного рабочего сценария.

Бот пока не запущен: отсутствуют токен бота, OpenAI API-ключ и реальные Telegram IDs владельца, ученика, группы и двух топиков. Нужен ручной приёмочный прогон. Следующая точка входа — [[Practice_Log]].
